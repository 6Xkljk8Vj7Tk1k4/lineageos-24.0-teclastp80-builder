# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

An unofficial **LineageOS 24.0 (Android 17)** build for the **Teclast P80 G3M2** (Allwinner A133, 4× Cortex-A53, 2 GB RAM, stock Android 10 with kernel 4.9.170), a **proof of concept**, packaged as a Podman build environment. Teclast publishes no kernel source, so there is no device tree: the build is the generic target `lineage_arm64_bvN4` (arm64, vanilla, ext4) running on Teclast's own kernel, boot image and vendor partition. Android 17 expects kernel 5.10 or newer (eBPF networking, pidfd, EROFS, newer capabilities); on 4.9 it runs through compatibility patches.

Base: LineageOS `lineage-24.0` (release `cp2a`) plus TrebleDroid. TrebleDroid and MisterZtr had no Android 17 branch when this was put together (2026-10), so the patch sets come from two places, chosen per project in `patches/lineage-24.0/sets`: the GSI and LineageOS side from MisterZtr's LineageOS_gsi recipe at its `lineage-23.2` commit (TrebleDroid's device tree is the same for both), and the platform side from RestlessOS (`cawilliamson/treble_restlessos`, branch `android-17.0`, a GrapheneOS-based GSI and the only Android 17 port of TrebleDroid's patches, with its own patches for legacy vendor kernels). `patches/lineage-24.0/skip` leaves out what does not fit, and this repository's patches (`patches/lineage-24.0/`) hold the rebased upstream patches and the fixes for the tablet. The synced tree lives in the gitignored `src/`.

LineageOS 23.2 from the [lineageos-p80-builder](https://github.com/6Xkljk8Vj7Tk1k4/lineageos-p80-builder) repository is the previous build and is no longer maintained; 24.0 is the maintained version. This repository shares its build system, its tools, its device patches 0001–0018 and its Bluetooth patch; 24.0's audio HAL restart and `traced` fix (0024) and deep Doze (0026) are not in 23.2.

The repo is meant to be published on GitHub for other P80 G3M2 owners. Keep everything in English, generic and about this tablet only: no serial numbers, MAC addresses or other personal data, no signing keys, no details or paths of anyone's own machines, no references to other projects.

## Commands

Build the container image (only when `Containerfile` changes; `build.sh`, `manifests/` and `patches/` are bind-mounted from the checkout, so `git pull` needs no image rebuild):
```bash
podman build -t lineageos-p80-builder .
```

Prepare the bind-mounted directories once (the container runs as `builder`, uid 1000):
```bash
mkdir -p src ccache
podman unshare chown 1000:1000 src ccache
```

Full build, detached (`-e SKIP_SYNC=true` rebuilds the tree as it is; add `-e KEEP_GOING=true -e WITH_ADB_INSECURE=true -e DEBUG_PATCHES=true` for porting and test builds; `BUILD_JOBS=4` for a first build on a 32 GB machine, see *Host notes*):
```bash
podman run -d --rm --security-opt label=disable \
    -v "$(pwd)":/home/builder/repo:ro \
    -v "$(pwd)/src":/home/builder/android/lineage \
    -v "$(pwd)/ccache":/home/builder/ccache \
    -e BUILD_JOBS=4 \
    --name p80-build lineageos-p80-builder
```
(`--security-opt label=disable`: on SELinux hosts such as Fedora the container may not use home-directory files otherwise; no effect elsewhere. Avoid `:z`/`:Z` on these mounts: relabeling walks the whole tree, hundreds of GB under `src/`.)
Output: `src/out/target/product/generic_arm64/p80/lineage-24.0-<date>-UNOFFICIAL-P80[-adb-insecure][-debug].img` and `SHA256SUMS`. Progress: `podman logs -f p80-build` or `src/logs/build-*.log`.

Environment variables of `build.sh`: `BRANCH` (`lineage-24.0`), `TARGET` (`lineage_arm64_bvN4`), `RELEASE` (`cp2a`), `BUILD_TYPE` (`userdebug`), `SYNC_JOBS` (4), `SYNC_RETRIES` (5), `BUILD_JOBS` (`nproc`), `CCACHE_SIZE` (30G), `MIN_FREE_GB` (15), `SYNC_ONLY` (sync and patch only), `NO_PATCHES` (sync only, for porting to a new branch), `SKIP_SYNC`, `DEBUG_PATCHES` (also apply `patches/<BRANCH>-debug/`), `KEEP_GOING` (`m -k`), `SUPER_BUDGET` (2514841600, see *Partitions and the super budget*); anything else reaches the build system through the environment, e.g. `WITH_ADB_INSECURE` or `P80_UPDATER_URI` (device patch 0019 turns it into `lineage.updater.uri` for someone who runs an update server; unset by default, and this repository makes no update packages).

## Architecture

- `Containerfile`: Ubuntu 20.04 + the LineageOS build dependencies + OpenJDK 17 + `repo`, user `builder` (uid 1000), ccache at `/home/builder/ccache`, `safe.directory '*'` (the bind-mounted tree belongs to another uid). `ENTRYPOINT` is `/home/builder/repo/build.sh` from the bind-mounted checkout.
- `build.sh` (cwd = `src/`): log to `src/logs/build-<UTC>.log` → free-space watchdog (below `MIN_FREE_GB` it kills the process group) → `repo init` every run (`--depth=1 --git-lfs -g default,-darwin,-mips,-notdefault`) → `manifests/treble-<BRANCH>.xml` as local manifest → `clean_interrupted_sync` + `repo sync` with retries (`GIT_HTTP_LOW_SPEED_LIMIT/TIME` against fetches that stall forever) → patches → `bash -n device/phh/treble/rw-system.sh` (a syntax error makes that boot script die silently halfway) → `SYNC_ONLY` stops here → `lunch lineage_arm64_bvN4-cp2a-userdebug` → `m systemimage simg2img` → the image: raw ext4, AVB footer erased (verification is disabled on the tablet and the hash tree costs ~40 MB of the super budget), named after `ro.lineage.version`, `SHA256SUMS`, a hard failure above `SUPER_BUDGET`. Long commands go through `run` (background + `wait`) because bash as PID 1 runs a signal handler only after the foreground command has ended.
- `clean_interrupted_sync`: an interrupted sync poisons the next one. repo treats a project without a `shallow` file as manually unshallowed and fetches its complete history, and a project whose checkout was killed has HEAD at the right revision, so repo skips it and leaves a half-empty worktree. The function removes such gitdirs and `.git` links, stale locks and temporary packs before every attempt.
- Patches, per project: the upstream sets in the order of `patches/<BRANCH>/sets` (one line per set: `<name> <directory in the tree> <filter>`, filter `all`, `only:<dir>,…` or `except:<dir>,…`, directories named like `platform_frameworks_base` and mapped to project paths as in LineageOS_gsi's `apply-patches.sh`, plus `platform_system_fs_fs_mgr` → `system/fs/fs_mgr`), then ours from `patches/<BRANCH>/<project path>/`, then `patches/<BRANCH>-debug/` with `DEBUG_PATCHES=true`. Without a `sets` file the three LineageOS_gsi sets are used, as on 23.2. `patches/<BRANCH>/skip` lists upstream patches to leave out (`<set name>/<directory>/<file>`, reasons as comments). Each patched project is reset to `m/<BRANCH>` and patched with `git am --3way`; a patch LineageOS has meanwhile merged (it reverse-applies) is logged and skipped, any other failure stops the build with the patch name. An `applied-patches` marker in the project's gitdir skips projects already in exactly that state, and files whose content did not change get their old mtime back, so one new patch does not make Soong and Kati re-read every patched `Android.bp`/`*.mk`. A project with no patches left goes back to `m/<BRANCH>`. The 24.0 tree ends up with 338 patches in 39 projects, 47 of them from `patches/lineage-24.0/`.
- `set -euo pipefail` throughout (`set +u` from `envsetup.sh` on): never end a pipeline inside a command substitution with `head`, the SIGPIPE ends the script silently (it once skipped the super budget check); `sed -n 1p` reads to the end.

### Editing patches

- Our patches are `git format-patch` files (author `P80 builder <builder@localhost>`; rebased upstream patches keep their original author), one change each, the commit message says why. Create them inside the container, where every project in `src/` is in its patched state after a build: `podman run --rm -it --entrypoint bash --security-opt label=disable -v "$(pwd)/src":/home/builder/android/lineage lineageos-p80-builder`, commit the change on top with `git -c user.name="P80 builder" -c user.email=builder@localhost commit` (the container's own git identity is `LineageOS builder`), `git format-patch -1 --stdout`, then `git reset --hard HEAD~1` (the next build re-applies everything). To change an earlier patch, re-apply the series in a `git worktree` at the commit before it, amend and re-export, and re-export the later patches of the same file too, so their `index` lines and hunk headers stay right.
- Rebasing an upstream patch that fails on LineageOS: apply the patches before it, apply it with `git apply --reject`, fix the rejected hunks by hand, commit with the original author and message (add a note on what changed), export it under the same file name into `patches/<BRANCH>/<project>/` and list the original in `skip`.
- The tree is a shallow `repo` checkout: `git am --3way` cannot build fake ancestors there ("sha1 information is lacking"), so a patch that only applies with a 3-way merge has to be regenerated, e.g. from a full clone of the upstream project.
- Do not run git on the host inside `src/`: with rootless Podman the files belong to a subordinate uid, git may not see the project's `.git` and falls back to an enclosing repository. Use the container. To test a changed patch series without touching the tree, mount `src/` as a throwaway overlay (`-v "$(pwd)/src":/home/builder/android/lineage:O`), delete the `applied-patches` markers in it and run `build.sh` with `SKIP_SYNC=true SYNC_ONLY=true`: every patched project is reset and patched again, and the overlay is discarded when the container exits.

### This repository's patches

`device/phh/treble` (TrebleDroid's device tree, the same base as on 23.2; 0001–0018 are unchanged from the 23.2 repository):
- **0001** `bluetooth.core.le.vendor_capabilities.enabled=false`: the Unisoc UWE5622 controller answers the vendor APCF command (`LE_ADV_FILTER`, 0xfd57, sub-command 0xff) with "Unknown HCI Command" twice, as Command Complete and as Command Status, and gd's HciLayer aborts on the second event. Without vendor capabilities the stack never sends APCF. (RestlessOS's personal Bluetooth patch for legacy controllers is outside the `rl-personal` selection; this property is enough here.)
- **0002** LineageOS's adb defaults instead of TrebleDroid's `persist.sys.usb.config=adb`.
- **0003** only VNDK 29 (the vendor's); the other VNDK snapshots cost ~380 MB that `super` does not have.
- **0004** The vendor's `android.hardware.configstore@1.1-service` dies with SIGSYS right after every start (`libminijail: blocked syscall: gettid`: newer libraries call `gettid()`, its Android 10 seccomp policy does not allow it), SurfaceFlinger waits for `ISurfaceFlingerConfigs` forever and the watchdog kills `system_server`. `rw-system.sh` (runs `on post-fs` in the `phhsu_daemon` domain) copies the policy to `/mnt/phh`, appends `gettid: 1`, restores the SELinux context and bind-mounts it over the vendor file.
- **0005** TrebleDroid's `rw-system.sh` switched privapp permissions to `log`; the vendor's `enforce` stays.
- **0006** model P80, brand and manufacturer Teclast, `ro.build.characteristics=tablet`.
- **0007** LineageOS's `common_full_tablet_wifionly.mk` instead of the phone configuration: not voice/SMS/data capable, no SIM slots.
- **0008** no telephony, IMS or fingerprint feature files (TrebleDroid declares them for every device), no TrebleApp, and of TrebleDroid's ~450 device overlays only highpriomisc, NightMode and Tethering (0013 then drops NightMode).
- **0009** the launcher, Settings, setup wizard and browser are compiled with `speed` at build time.
- **0010** 720p camcorder profile: the vendor's `/vendor/etc/media_profiles_V1_0.xml` stops at 480p, although the rear camera (2 MP) delivers 1280×720 at 30 fps. `rw-system.sh` bind-mounts a system copy with 720p for camera 0 (after `chmod 0644`: under init's umask 077 the copy was 0600 and the zygote's `MediaProfiles` preload aborted).
- **0011** no phone apps (Dialer, Messaging, SIM toolkit, IMS entitlement).
- **0012** `persist.sys.sf.color_saturation=1.0`, i.e. the Natural color mode by default. In the Boosted mode ColorDisplayService sets a color matrix the Allwinner composer ("SUNXI HWC") cannot apply, so SurfaceFlinger composed every layer on the GPU (`CLIENT`); with Natural all layers are `DEVICE`.
- **0013** no color modes, Night Light or extra dim, which would all need GPU composition (`config_setColorTransformAccelerated=false` over LineageOS's common overlay; `config_nightDisplayAvailable` and `config_reduceBrightColorsAvailable` default to it), and TrebleDroid's NightMode overlay (accelerated color transforms) is dropped.
- **0014** no wallet tile or power-menu plugin, no hotspot or tethering (`ro.tether.denied`); overrides `quick_settings_tiles_default` and Android 16's `quick_settings_tiles_new_default` (Android 17's list: 0025).
- **0015** the vendor HALs' debug logging (`audio_platform`, `AW_PowerHAL`) raised to warning through `log.tag.*` properties.
- **0016** `PRODUCT_ENABLE_UFFD_GC := false`: kernel 4.9 has no userfaultfd, ART runs the concurrent copying GC and would reject every prebuilt odex compiled for the userfaultfd GC (Android 17's ART still falls back to concurrent copying).
- **0017** the stock firmware's memory settings: `ro.config.per_app_memcg=false`, `ro.lmk.critical_upgrade=true`, `dalvik.vm.heapgrowthlimit=128m`, and `ro.lmk.kill_heaviest_task=false` (TrebleDroid's default is true; the stock vendor sets false itself). With `ro.config.low_ram` and no explicit setting, lmkd puts every app into its own memory cgroup with a soft limit, and the 4.9 kernel's cgroup v1 soft-limit reclaim swaps exactly those apps out.
- **0018** LineageOS's naming for unofficial builds, `24.0-<date>-UNOFFICIAL-P80`.
- **0019** optional update server: with `P80_UPDATER_URI` set at build time (`-e P80_UPDATER_URI=...`; unset by default), `lineage.updater.uri` points LineageOS's Updater to it; otherwise LineageOS's default stays, which has nothing for this tablet. No server is written into the tree. Later patches use its lines as context, so keep it.
- **0020** `android.hardware.lights-service.p80` (`p80-lights/`): Android 17 removed the framework's HIDL `light@2.0` client (AOSP 459627afd2, https://github.com/LineageOS/android_frameworks_base/commit/459627afd234c352d9e9a7f780f07ad1f825b110), and the rewritten `LightsService` only waits for the AIDL `ILights/default`, while the P80 has no `/sys/class/backlight` and drives the backlight through the vendor's HIDL `light@2.0` service (`lights.ceres.so`). The service serves AIDL `ILights` V2 from the system partition (framework VINTF fragment, own `hal_light_p80` domain, `class hal`, like TrebleDroid's `sysbta`) and forwards `getLights()`/`setLightState()` (the AIDL and HIDL enums share their values); it uses `tryGetService()` so a vendor without a light HAL cannot block `system_server`. Needs the `light@2.0` definitions from RestlessOS hardware/interfaces 0001. Verified: brightness 30/200/102 in Settings reaches the vendor HAL as `ff242424`/`ffcacaca`/`ff6a6a6a`.
- **0021** RestlessOS device 0029, copied (its device set stays out): Android 17 added `getLeAudioAseCodecConfiguredParameters` to the Bluetooth audio AIDL interface (V6), which left phh's system Bluetooth audio providers abstract.
- **0022** RestlessOS device 0030, copied: Android 17's `host_init_verifier` rejects services without `user` that would run as root ("it would have been root"; `vndk.rc`, `phh-remotectl.rc`, `adbd.rc`), so they declare `user root`.
- **0023** no desktop windowing: LineageOS 24.0 sets `config_isDesktopModeSupported` in its common overlay and `config_canInternalDisplayHostDesktops` for tablets. `ro.config.low_ram` (stock P80) makes ActivityTaskManager report no multi-window and so no freeform support, while WMShell's `DesktopModeStatus` only looks at the resources: SystemUI crash-looped (`wmshell.main`: "Can't create root task for unsupported windowingMode=5" from `DesktopDisplayEventHandler.createDefaultDesksIfNeeded`), and the keyguard and the setup wizard were never drawn.
- **0024** `p80/p80.rc` with two init rules. The vendor's audio HAL (`vendor.audio-hal-2-0`) is a oneshot service that only Android 10's `audioserver.rc` restarted (`onrestart restart vendor.audio-hal-2-0`): after it died (a `dumpsys media.audio_flinger | grep -m1` killed it with SIGPIPE: the HAL writes its dump into the pipe itself), audioserver came back without it and there was no sound until a reboot; now `on property:init.svc.audioserver=restarting` restarts it. And `traced.relay_producer_port` is cleared at early-init: AVF sets it to `vsock://-1:2010`, kernel 4.9 classes AF_VSOCK sockets as plain `socket` (no `extended_socket_class`), which `traced.te` does not allow, so traced crash-looped ("Failed to create vsock://-1:2010"; the same on 23.2). There are no VMs here (no `/dev/kvm`).
- **0025** Android 17's SystemUI splits the internet tile into Wi-Fi and mobile data and reads `quick_settings_tiles_default_split`: overridden without `wallet` and `cell`.
- **0026** deep Doze: `DeviceIdleController.scheduleAlarmLocked()` returns early while `config_autoPowerModeUseMotionSensor` is true and there is no significant-motion sensor, so the P80 (accelerometer only) never left light idle (96 % light idle, no deep idle in 2-hour standby tests on 23.2 and 24.0). The overlay sets it to false (`dumpsys deviceidle`: `mDeepEnabled=true`).
- **0027** AudioFX, SecureElement, TeleService and ONS left out: the first three run as persistent processes from boot even when disabled with `pm disable` (~6, ~6 and ~16 MB PSS). The tablet has no secure element, NFC or eSIM, AudioFX is optional, and TeleService returns from `PhoneGlobals.onCreate()` right away without `FEATURE_TELEPHONY`, serving nothing. ONS (`com.android.ons`, persistent, for devices with SIM cards) shares `android.uid.phone` and the com.android.phone process with TeleService and requests only `RECEIVE_BOOT_COMPLETED` and `READ_PHONE_STATE`; its `ACCESS_NETWORK_STATE` came from TeleService's manifest, so a build without TeleService alone crash-looped ONS (`SecurityException` from `ConnectivityService.listenForNetwork` in `ONSProfileActivator`, ~180 restarts a minute, ~30 % CPU at idle). When removing a package from a shared user, check what the other members got through it.
- **0028** 64-bit apps only: the Android 10 vendor's `ro.zygote=zygote64_32` keeps a 32-bit zygote with its preloaded framework running (~75 MB PSS, the third-largest process) for 32-bit-only apps the system does not have. `ro.zygote=zygote64` and the product ABI lists come from the product partition, which init reads last and uses first when it derives `ro.product.cpu.abilist*`. The vendor's 32-bit HALs (e.g. the OMX codecs) are separate processes and keep running.
- **0029** `vm.swappiness` 100 after boot: zram (lz4, 75 % of RAM) is the only swap, and the kernel default of 60 drops more file pages (code) that the eMMC has to read back. Measured: notification shade 49 % instead of 56 % janky frames, app starts as fast or faster, more memory left after eight apps.

Other projects:
- **build/soong 0001** restores the `/system/lib{,64}/vndk{,-sp}-<ver>` symlinks into the VNDK APEX for VNDK 29 and older, which Android 16's `makeCompatSymlinks()` created and Android 17 dropped. The Android 10 VNDK-SP `libhidlbase` looks for passthrough implementations (`android.hidl.memory@1.0-impl`) in `/system/${LIB}/vndk-sp-29/hw/`; without them the vendor's `media.codec` failed every buffer (`libhidlmemory: Could not fetch mapper for ashmem shared memory`, `useBuffer() failed to map memory`, NO_MEMORY): no hardware video recording or playback. RestlessOS restores the links in `target/product/gsi/Android.bp`, which only the Soong-defined system image uses (`PRODUCT_SOONG_DEFINED_SYSTEM_IMAGE`, set by `aosp_arm64.mk`, not by this product).
- **frameworks/base 0100** TrebleDroid's reverts that restore `StorageManager.isEncryptable()` & co. and `TelephonyManager.NETWORK_CLASS_*` document them with the inline `{@hide}`; Android 17's Metalava treats those as public API (`api-stubs-docs-non-updatable`: "New API must be flagged with @FlaggedApi"). Block `@hide` tags keep them hidden as on Android 16; a block tag only counts at the start of a comment line, so the `NETWORK_CLASS_*` fields get multi-line comments. (RestlessOS personal base 0019 lists them in `current.txt` instead, which does not satisfy the flag check; skipped.)
- **frameworks/base 0101** Bluetooth off by default (`def_bluetooth_on`; Hikari-no-Tenshi's patch from MisterZtr's set, which the 23.2 build leaves out): saves ~28 MB while off.
- **packages/apps/SetupWizard 0001** LineageOS's SetupWizard uses its wide welcome layout (logo and a 57 sp title in one row with two large buttons) from `w600dp`; the P80 in portrait is w601dp, so "Welcome to LineageOS" wrapped into a narrow column. The layout and its dimens move to `w840dp`.
- **packages/modules/Bluetooth 0001** (as on 23.2): on every suspend and resume the Unisoc WCN kernel driver sends its own vendor commands (`0xFD09`, at suspend also `0xFD0D`), and the controller's responses reach the stack, which aborts (`Received COMMAND_COMPLETE(0x0e) event with OpCode Unknown OpCode(0xfd09) without a waiting command`). The patch drops Command Complete/Status events of vendor-specific opcodes (OGF 0x3f) the stack is not waiting for, with a warning. Verified on 23.2: 39 suspends in 25 minutes, 144 dropped events, no crash.
- **packages/modules/Connectivity 0002** without the netd BPF maps (this kernel), `NetworkStatsService.setKernelCounterSet()` logged a WTF with a stack trace for every uid foreground/background change (~10 a minute while switching apps); it now warns once. The other remaining WTFs (stats polling, `ClatCoordinator`) come at boot or every 30 minutes and stay.
- **packages/modules/Virtualization 0001** `com.android.virt` is the only APEX with an EROFS payload in Android 17 (compressed, 66 MB; Android 16 used ext4, 99 MB), and the 4.9 kernel has no EROFS. As a bootstrap APEX (early VM) it took down apexd-bootstrap and init rebooted into the bootloader (`bootloader,bootstrap-apexd-failed`); without early VM it stayed inactive and the boot image did not match the boot classpath (DSU boot 1). The patch drops the EROFS setting (ext4 payload, ~34 MB more in the image).
- **system/memory/lmkd 0100** Android 17's lmkd returns from process registration when `pidfd_open()` (Linux 5.3) fails (`pidfd_open for pid N failed; errno=38` for every app on 4.9), so it tracked no process and could never kill; the kill-wait code would also hand a PID to `epoll_ctl()` and `close()` it, and the reaper's last resort is `pidfd_send_signal()` (5.1). The patch restores Android 16's paths without pidfd (`/proc/<pid>` polling, `kill(2)`). Verified: under pressure lmkd killed cached and background processes in `oom_score_adj` order.
- **system/sepolicy 0100** Android 17 grants `open` on `ashmem_libcutils_device` only through the vendor policy or, for old vendors, the 31.0+ compat files; TrebleDroid's restored 28.0–30.0 compat files lack it. The 4.9 kernel's memfd has no `F_SEAL_FUTURE_WRITE`, so libcutils and ART fall back to ashmem (`fcntl(F_ADD_SEALS) failed … no memfd support`), and zygote got `avc: denied { open }`. The patch adds Google's line to the three compat files.
- **system/zygote 0001** `zygote_next`, Android 17's Rust zygote (species `android-native-app`, it spawns e.g. a browser's GPU process as a native isolated service), drops every capability outside the requested bounding set, including CAP_PERFMON, CAP_BPF and CAP_CHECKPOINT_RESTORE (Linux 5.8/5.9). 4.9 answers `PR_CAPBSET_READ` with EINVAL for those and `.expect("Failed to check capability bound")` aborted every child (SIGABRT as "zygote-child", no tombstone): a current Chromium-based browser (targetSdk 37) died at start with "Timed out waiting for GPU channel". The Java zygote stops at the first EINVAL; the patch treats an unknown capability as not in the set and logs it. (RestlessOS personal `platform_system_zygote/0001` makes the same change plus tolerance for failing cgroup creation; it is outside the `rl-personal` selection, and cgroup creation works on the P80.)

`patches/lineage-24.0-debug/` (`DEBUG_PATCHES=true`, never publish such images): **9001** `persist.logd.size=1M` (low-RAM devices default to 64 kB log buffers, which overflow before adb comes up); **9002** a "black box": `kernel.panic=10` at early-init (the kernel has `CONFIG_PANIC_TIMEOUT=0`, a panic hangs), and a `p80-debug` service from `on init` writes dmesg, logcat, properties and processes to `/metadata/p80-debug/` every 5 s and reboots through sysrq after 10 minutes without `sys.boot_completed`. 23.2's third debug patch (no `reboot_on_failure` for NetBpfLoad) is not needed: 24.0's loader rc files have none left.

### Other findings, no patch needed

- eBPF: NetBpfLoad and netd continue in degraded mode on 4.9; netd's socket filter programs are missing (`Failed to get program from /sys/fs/bpf/netd_shared/prog_netd_skfilter_*`) and StrictController's iptables rules fail (no `CONNMARK` target in the kernel); netd continues. Expected without the programs: no per-app data accounting, firewall or VPN lockdown (not tested). The kernel has `CONFIG_BPF_SYSCALL` but no `CONFIG_BPF_JIT`. Never fake the kernel version with `ro.bpf.kver_override`.
- The framework still uses the vendor's HIDL power HAL; `rw-system.sh` still exits with status 1 at its last line (a Lenovo pen write), harmless.
- The kernel has no cpusets, schedtune or blkio cgroups: init's task-profile errors are harmless and the same on stock.
- Media: Teclast's OMX codecs (`OMX.allwinner.video.*`; 84 OMX codecs listed) work with Android 17 once the VNDK-SP links are there.
- Wi-Fi: `sprdwl_ng` has no WPA3-SAE (Android hides WPA3-only networks) and the country code stays `null` without a modem (`cmd wifi force-country-code enabled <CC>` for testing).
- Time zone: after the setup wizard it was GMT (23.2's wizard picked Pacific/Midway); nothing detects it without telephony or a location time zone provider.
- Log noise without effect: SurfaceFlinger `PresentLatencyTracker` "Too many pending frames" (the Allwinner composer's present fences), fs-verity unsupported for permission and package files (written anyway, as on 16), Wi-Fi aware, carrier config and IMEI messages on a Wi-Fi-only tablet. Remaining SELinux denials: Settings (`system_app`) probing services it may not use and LineageOS's absent touch-gesture HAL, the vendor Bluetooth HAL setting a `default_prop`.
- Never pipe a vendor-backed `dumpsys` into a reader that exits early (`grep -q`, `grep -m1`, `head`): the vendor audio HAL writes its dump into the pipe itself and dies of SIGPIPE. `tools/p80-selftest.sh` uses `has()`, a grep that reads all of its input.
- `zygote_next` starts at boot only after an app has used a native isolated service (`persist.zygote.zygote_next.start_on_boot`, set by the framework as a prewarm).
- After DSU tests, run `tools/p80-dsu.sh --wipe` and check that `/metadata/gsi/dsu/` is empty: gsid's own wipe keeps the `active` slot file, and the helper removes it together with its own `lp_metadata` and `lp_names`. `com.android.dynsystem` starting at every boot is normal and not caused by DSU leftovers: its `BootCompletedReceiver` starts it on every boot, the service stops itself when no DSU is installed or running, and the process then stays cached.
- Release builds without `WITH_ADB_INSECURE` set `ro.debuggable=0` (LineageOS's `PRODUCT_NOT_DEBUGGABLE_IN_USERDEBUG`); Developer options → "Rooted debugging" still allows `adb root`. With USB debugging off the tablet does not enumerate on USB at all.

### Partitions and the super budget

`sys_partition.fex`: bootloader 32 MiB, env 16, boot 32, **super 2.5 GiB**, misc 16, recovery 32, cache 1.5 GiB (unused), vbmeta/vbmeta_system/vbmeta_vendor 16 each, metadata 16, private 16, frp 0.5 (holds the OEM-unlock byte), dtbo 2, media_data 16, UDISK the rest. `super` (group `sb`, maximum 2,675,965,952 bytes) holds `system` 884,772,864, `vendor` 156,930,048 and `product` 1,134,882,816 bytes on stock. With `product` replaced by a 4 MiB empty ext4, **the system image may be at most 2,514,841,600 bytes** (`SUPER_BUDGET`). The 24.0 image was 2,397,114,368 bytes for the tested build (112 MiB to spare; the ext4 virt APEX adds ~34 MB) and 2,374,615,040 bytes with the additions listed in *Status*, item 2 (133 MiB to spare).

### Flashing, in detail

- `fastboot oem unlock` answers `OKAY` in a fraction of a second, without a prompt on the screen, and erases `UDISK`; "Ability is 0" means the OEM-unlocking switch (last byte of `frp`) is off. Afterwards the bootloader refuses most commands, `getvar` included, with `secure mode,fastboot limited used`; `fastboot flashing unlock` is unknown. Everything else happens in fastbootd (`fastboot reboot fastboot`, whose host command may time out while the tablet reboots; `adb reboot fastboot` from Android goes there directly).
- fastbootd: `max-download-size` 512 MiB (fastboot splits raw images itself; "Invalid sparse file format at header magic" is informational), it resizes the logical `system` partition when flashing (121 s for the 24.0 image), it does not know `cache`, and `fastboot -w` targets a `userdata` partition that does not exist: use `fastboot erase UDISK`.
- vbmeta: Teclast's own `vbmeta.img` (`vbmeta.fex` in the firmware) flashed with `--disable-verity --disable-verification`; `vbmeta_system` and `vbmeta_vendor` stay stock. The system image carries no AVB footer.
- From 23.2 to 24.0 the tested path was `adb reboot fastboot` → `fastboot flash system` → `fastboot erase UDISK` → `fastboot reboot` (Android 17 data cannot go back to 16, and an upgrade with the data kept is untested). The first boot after erasing `UDISK` formats the data partition and reboots once (`sys.boot.reason=reboot,factory_reset`).
- Avoid: `fastboot reboot recovery` (on a PF1506 photo frame with the same A133 platform it left the device in a recovery menu without USB: https://github.com/OdyNobody/photo-frame-dashboard/blob/ben-pf1506-review/docs/pf1506-a133-lineageos.md); reading `/sys/power/wakeup_count` over adb (it blocks while wakeup events are active, i.e. always with USB connected); `setenforce 0` or other SELinux changes for tests.
- Never flash Teclast's Android 11 firmware for the G3M3 (`P80_EEA`, kernel 5.4) on a G3M2: another manufacturer's board with other panels, touch configuration, cameras and DRAM tables.
- Stock firmware: Teclast's firmware lookup https://www.teclast.com/en/firmware/fchk.php?c=G3M2 (EEA V1.04: `P80(G3M2)_Android 10.0_EEA_V1.04_SZ.rar`, 961,783,684 bytes, SHA-256 `72919fc0c7598ad93994d19f65849fa7747961f19d8997c377d56fe3bf30bbf3`). The RAR holds `Firmware/Firmware.img`, an unencrypted PhoenixSuit IMAGEWTY v0x300 image (`tools/imagewty_extract.py` lists and extracts its items), plus PhoenixSuit for Windows and Teclast's instructions. `super.fex` is an Android sparse image (`simg2img`, then `lpdump`/`lpunpack`). Back to stock from fastbootd (untested): Teclast's `system`, `product`, `vendor` and the unmodified `vbmeta`, then `fastboot erase UDISK`.

## Testing

- `tools/p80-selftest.sh [--reboot]` (adb): identity, SELinux, privapp, adb authorization, boot health (crash buffer, restarting services, watchdog, seccomp), the patches' effects (configstore policy, 720p profile, no telephony, wallet, tethering or color modes), Settings and quick-settings UI through uiautomator, composition and color matrix, dexopt state, memory settings, Wi-Fi, internet and DNS, Bluetooth off/on, audio, cameras, codecs, accelerometer; with `--reboot` also the boot time. The exit code is the number of failures; root-only checks are skipped without `adb root`. It runs unchanged on 23.2 and 24.0.
- `tools/p80-appswitch.sh [rounds]`: launches 8 apps per round with `am start -W` and reports COLD/WARM/HOT and times, kswapd CPU, major faults, swap traffic, memory PSI, lmkd kills and new ANRs. Run it right after a boot or a framework restart.
- **DSU** (`tools/p80-dsu.sh <image>`, `--wipe` removes it; needs `adb root` on the installed system) boots another system image once from `/data/gsi/dsu` with a fresh 4 GB userdata; the installed system and its data stay untouched and the next reboot returns to it. Three workarounds for this tablet: gsid may not read `/data/local/tmp` (SELinux), so the image goes through a pipe; the boot image's first-stage init is Android 10's, which reads the DSU partition table from `/metadata/gsi/dsu/lp_metadata` (newer gsid writes it per slot) and finds the backing partition only by its GPT name (`UDISK`, not `mmcblk0p17`; `tools/lp_metadata_rename.py` rewrites it and fixes the checksums); and it does not write `/metadata/gsi/dsu/lp_names`, without which Android 16's `fs_mgr` failed the whole fstab (no `/data`, only the bootstrap APEXes, a black screen). Every new DSU image means a new userdata, so the setup wizard again and "Rooted debugging" off: use `WITH_ADB_INSECURE=true` test builds for DSU (a DSU boot of the release build gave no usable adb, every command "error: closed"). The one-shot boot works across Android versions.
- Boot problems before adb: `DEBUG_PATCHES=true` adds the black box (`/metadata/p80-debug/`, read it from the installed system afterwards and delete it: `/metadata` has 16 MiB) and 1 MB log buffers. It starts at `on init`, so failures in early-init (apexd-bootstrap) leave nothing there: read `sys.boot.reason` on the installed system instead.
- Sleep: the tablet never suspends while USB is connected to a computer (kernel wakeup source `usb_connecting` in `/sys/kernel/debug/wakeup_sources`). For suspend or battery tests unplug it and read the results afterwards (`/sys/kernel/debug/suspend_stats`, `dumpsys batterystats`; enlarge the log buffers first with `logcat -G 4M`). On 23.2 about 85 % of the standby charge went while the SoC was suspended (healthd's current right after a resume reads 46–59 mA) and each suspend took 1.1–1.7 s in Teclast's display and touch drivers: the remaining floor is kernel work.
- Release check: SELinux enforcing, empty crash buffer (`logcat -b crash -d`), no `restarting` services, `traced` running (`getprop init.svc.traced`; a crash loop ends `stopped`, which the restarting check misses), suspend on battery.

### Memory and performance

Measured on the installed build, each variant with the same probe (reboot, 150 s idle, `dumpsys meminfo`, `tools/p80-appswitch.sh 2`, a scripted UI run through the launcher's app drawer, the notification shade and Settings, then lmkd under a 600 MB buffer with `oom_score_adj` 0). Baseline: 981 MB available after boot, Used RAM 1.26 GB; app switching 12.1 s / 3.0 s (round 1 / round 2, 7 of 8 hot); janky frames launcher 18.7 %, shade 57 %, Settings 5.3 %; lmkd 35 kills under pressure, no kernel OOM kill. Largest processes (PSS): system_server 257 MB, SystemUI 168 MB (63 MB of it its speed-compiled odex, file pages), the 32-bit zygote 75 MB, launcher 60 MB, webview_zygote 34 MB, zygote64 33 MB, Bluetooth 28 MB plus TrebleDroid's system Bluetooth audio HAL 15 MB, zygote_next 16 MB, com.android.phone 16 MB, AudioFX and com.android.se 5–7 MB each.

- **Taken:** 64-bit apps only (0028, ~75 MB), AudioFX, SecureElement and TeleService out (0027, ~27 MB; ONS has to go with TeleService), Bluetooth off by default (frameworks/base 0101, 28 MB while off), `vm.swappiness` 100 (0029: shade 49 % instead of 56 % janky frames, app switching 11.5 / 2.9 s vs 11.6 / 2.9 s, more memory left; memory PSI full 1.05 vs 0.83 s).
- **Measured and rejected:** the deadline I/O scheduler (cfq stays: differences in both directions within noise); ART heap tuning (heapmaxfree 4m, heaptargetutilization 0.80, heapstartsize 4m: 10–16 MB less memory, but the shade went from 52 % to 62 % janky frames with a 150 ms 90th percentile, the launcher from 17.5 % to 21.4 %, app switching 0.1–0.15 s slower).
- **Checked, nothing to do:** schedutil reaches the top frequency within ~0.2 s of a touch (power hints work), the GPU's `simple_ondemand` devfreq (252–504 MHz), zram lz4 with page-cluster 0, lmkd on PSI with the stock thresholds, prebuilt code in use (SystemUI's odex resident).
- **Result with all of them (build with 0027 including ONS, 2026-10-31):** 1,031 MB available after boot, Used RAM 1.13 GB; app switching 11.5 s / 3.0 s, 711 MB available afterwards (baseline 656 MB); janky frames launcher 19.0 %, shade 59 %, Settings 4.9 % (the shade varies by a few points between runs); lmkd 32 kills under the 600 MB buffer, no kernel OOM kill.
- **Left as options for users:** animation scales 0.5x (perceived speed).

## Outlook

- **The stock 4.9 kernel is the limit.** Android 17's `NetBpfLoad` (lineage-24.0) aborts below kernel 5.10 and without a BPF JIT (https://github.com/LineageOS/android_packages_modules_Connectivity/blob/lineage-24.0/bpf/loader/NetBpfLoad.cpp); this build only runs because RestlessOS's patches turn those checks and every missing program into warnings, at the price of the eBPF network features. LineageOS itself requires 5.4 since 23 (https://lineageos.org/Changelog-30/). Each Android release adds such assumptions (pidfd, capabilities, EROFS, ueventd paths in this one), so every later LineageOS version will need more of these patches.
- **An own kernel looks possible.** The A133 runs in secure mode, but the root key hash is not burned, and the boot ROM accepts any root key until it is ("until the ROTPK_HASH eFuse is programmed, any 'root key' will be accepted by the BROM", mainline U-Boot `tools/sunxi_toc0.c`): a self-signed TOC0 could start an own bootloader with an own device tree. Untested; a microSD card is the safe first experiment, and FEL stays reachable.
- **Kernel base:** Allwinner's longan 5.15 (public as https://github.com/chainsx/kernel-sun50iw10, branch `main`) carries the board drivers (display, video engine, cameras, UWE5622, touch, sensors, AXP803). The PowerVR kernel module matching the vendor's user-space DDK 1.11@5516664 is public in the longan 4.9 tree and would need a port to 5.15. Mainline Linux has basic support only (`sun50i-a133-teclast-p80.dts`, no display or GPU). The display panels' init sequences exist only in Teclast's kernel binary (as DWARF-typed tables in `vmlinux`). Teclast does not publish the kernel source and declined a request for it. With a 5.15 kernel with BPF JIT, the BPF-less parts and the lmkd and zygote patches could go.

## Host notes

- Disk: the synced 24.0 tree takes ~135 GB (32 GB of it git data in `.repo`), a full build adds ~117 GB in `out/`, ccache ~26 GB: ~300 GB in total. The free-space watchdog stops the build before the disk fills.
- RAM: siso (Android 17's ninja replacement) holds the build graph in ~20 GB of memory, and late in the build R8 runs several Java processes with up to 4 GB heap each. With about 30 GB of RAM, `BUILD_JOBS=4` got the first build through the R8 phase without thrashing (more jobs swapped heavily); small incremental builds work with the default. Do not run two Android builds on one machine at the same time.
- Time: Soong's first analysis of the 24.0 tree takes 17–24 minutes, a resumed build ~2 minutes, a build after a changed glob ~10 minutes; small changes build in 5–20 minutes.
- Never write into `src/` outside `out/` between incremental builds: Soong re-runs every glob whose directory changed, and a changed result starts the full analysis again (`Globs changed, rerunning soong... One culprit glob` in the log names the cause). Run Python tools from the tree with `python3 -B`.
- Rootless Podman: `podman unshare chown 1000:1000 src ccache` gives the container user the folders; files under `src/` then belong to a subordinate uid, so read them normally and delete them with `podman unshare rm -rf src`. If the checkout's group is not mapped in the user namespace (e.g. a setgid group inherited from a parent directory), run `chgrp "$(id -gn)" src ccache && chmod g-s src ccache` first. The checkout must be world-readable (`o+rX`) for the container user.
